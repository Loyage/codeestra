- [ADR-0025](0025-runtime-lifecycle-stop-and-single-instance.md)：Runtime 生命周期可判定化。`codeestra stop` 改为「请求 + 有界等待 + 事实报告」（`STOPPED`/`NOT_EXITED` exit 0/1、`NOT_RUNNING` 不启动、`UNREACHABLE_PROCESS` exit 1 且**不杀进程**）；根因是各子系统把 `Bun.sleep(graceMs)` 放进 `Promise.race` 却从不清理 timer（Bun 会为 pending timer 保持事件循环，shutdown 跑完仍多活 ~5s），修复为清 timer 的 `withDeadline` + 顺序完成后确定性 `process.exit`（仅当没有未确认停止的 provider/验证进程）；启动改为 `runtime.lock`（硬链接原子写、`bootId/pid/startToken` 归属、owner 存活则拒绝、死后接管）+ 每次 boot 的 `runtime-boots/*.json` 痕迹，消除并发启动的双 Runtime、迁移崩溃与「socket 被并发启动者删除后不可达却永不退出」的竞态；新增只读诊断（CLI 直接读生命周期记录，不依赖 Runtime 存活、不写不删不发信号），自动回收不可达进程留待另立 ADR。
- [ADR-0029](0029-codex-adapter-transport-and-capabilities.md)：第二个真实 Adapter（Codex 0.151.0）接入。传输选 `codex app-server --stdio`（LF-JSONL JSON-RPC）而非 `exec --json`，因为只有它提供可承载 fail-closed gate 的审批应答通道、结构化提问、`turn/interrupt` 与 `thread/resume`；STRICT 复用 Codex 自己的 `untrusted` + `workspace-write` 审批策略并把请求映射到**既有** Attention 通道（FULL 则 `never` + `danger-full-access`，0 确认），不新增审批层。能力矩阵按实测填写：`cooperativeStop: REQUIRES_VALIDATION`（interrupt 不停已在跑的工具、杀 app-server 留孤儿）、`attach`/`reconnectToLiveSession`/`pause`/`revisionAcknowledgement: UNSUPPORTED`（Pi 的 ADR-0010/0023/0026 交接机制**不套用**）、`resumeAfterExit: SUPPORTED`（实测同 thread/同 rollout 路径）、新增 `controlledConfiguration: SUPPORTED|UNSUPPORTED`（Codex app-server 无 `--ignore-user-config`，ambient plugin/MCP/hook 参与执行）。interrupted turn 不产生 `completed` 证据（否则会写入假的 `toolsQuiescent`），改报 `disconnected`。记录未完成项：Runtime 目前没有 `FAILED → READY` 路径，因此「Execution 失败后换 Agent」只在 Execution 建立前失败或 pause→resume 路径上成立。

- [ADR-0028](0028-revision-delivery-and-stale-session-startup-reconcile.md)：修订投递确认与重启后 stale ACTIVE Session 的启动收敛（补齐 `## NEXT` 第 4 项）。投递是一等需求 + append-only 尝试台账（schema **v19**，只追加 `if (version < 19)`，v16 继续永久未使用）：**只有两个事实能满足它**——Adapter 返回带 evidence 的结构化 ACK，或停止后新建的 successor Execution 行被读回并确认 `applied_revision_id` 就是该 revision；「消息发出去了」永不当作确认。能力如实：`revisionAcknowledgement != SUPPORTED`、声明 SUPPORTED 但没有 `applyRevision` 端口、以及没有 evidence 的 ACK 分别记 `CHANNEL_UNSUPPORTED`/`UNACKNOWLEDGED`（Pi 仍 `UNSUPPORTED`，不声称热更新了规格）；不支持时唯一处置是既有「协作停止 + 新建 Execution」（`task revision delivery resolve --action stop-and-restart`，退出码 0 仅当确实满足），终止无法确认则 `RECOVERY_REQUIRED` 并保留现场；超时与重启中断的尝试按事实收口为 `TIMED_OUT`/`FAILED/RUNTIME_RESTARTED`，不自动重投。`reconcileStaleAgentSessions` 收敛 `agent_sessions`/`executions` 仍写 ACTIVE/RUNNING 的投影：按记录的 pid+start token 判所有权，**不写 RUNNING、不声称静止（进程树只是快照）、不发信号不杀进程、不删任何资源**，一律 `RECOVERY_REQUIRED` 并把观察值写进 append-only 台账与事件，幂等且不碰本代 Runtime 仍持有的 Session。命令面 `task revision create|list` 与 `task revision delivery list|get|resolve` 零确认、`--json`、退出码稳定。
