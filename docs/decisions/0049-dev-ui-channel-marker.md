# ADR-0049：dev 构建的 UI 必须有显眼通道标记（构建期变量 + 横幅 + 橙色强调）

Status：Accepted（用户 2026-09-15 决策）。无 schema 变更、不占迁移号；只改便利前端与一个构建脚本，
不新增 Runtime 语义、不新增确认（ADR-0008）。

## Context

ADR-0048 让 dev 与稳定两边可以同时运行。两个界面外观目前完全相同，用户无法一眼判断「我现在开的是不是
稳定版」，风险是把 dev 界面上的行为当成稳定行为，或反过来在稳定界面上找 dev 才有的改动。

用户要求：**dev 分支运行出来的界面必须有非常显眼的标志**，用于与 main 稳定代码的界面对照。

约束（来自既有决策）：UI 只是同一 Runtime 命令面的便利前端；验收只用 CLI/命令面与 HTTP 断言，
不使用 computer-use 或浏览器自动化；main 的构建产物不得被 dev 的标记污染（否则标记会随提升进入稳定分支）。

## Options

1. 机制：(a) 构建期环境变量（`VITE_CODEESTRA_CHANNEL=dev`）；(b) Runtime 在状态里报告通道，UI 读取；
   (c) 在 dev 分支源码里硬编码标记（合并到 main 时需反向删除）。
2. 视觉：(a) 顶部整条横幅 + 标题后缀；(b) 右上角角标；(c) 横幅 + 整体橙色强调色。

## Decision

用户选择 1(a)、2(c)。

### D01：通道是构建期事实

- 唯一的通道来源是构建期变量 `VITE_CODEESTRA_CHANNEL`；值恰为 `dev` 时为 dev 通道，未设置或任何其它值
  均为稳定通道（`stable`）。解析是大小写敏感的纯函数，不做模糊匹配。
- 不设置该变量时，**稳定通道的产出不携带任何通道痕迹**：`index.html` 逐字节不变（构建插件对稳定通道原样返回），页面不渲染任何标记元素、不写任何 `data-*` 属性、不改标题。main 检出继续只用 `bun run build:ui`。
  （注：共享的前端代码里仍包含横幅与覆盖规则的实现，所以「稳定产物与本次改动前逐字节相同」既不成立也不是本条主张；主张的是稳定通道不产生任何标记事实。）
- dev 构建的入口是新增脚本 `bun run build:ui:dev`（在根 `package.json`），它只注入该变量后调用同一个 vite 构建；
  dev 检出构建 dev 界面时使用它。
- 明确否掉运行期推断（路径、分支名、home 目录）与 Runtime 契约字段：它们要么不可靠（同一份产物可能被
  不同 home 托管），要么为「我在跑哪份代码」引入新的产品语义，而这个问题用构建期事实加显式 `CODEESTRA_HOME`
  已经可回答（ADR-0048 D05）。

### D02：标记的形态

- **构建期 HTML 标记**：dev 通道的构建把 `data-channel="dev"` 写进 `dist/index.html` 的 `<html>`，并把标题换成
  `Codeestra DEV`。这使标记与橙色强调在**任何 JavaScript 运行之前**就存在（首次绘制不再先闪一下稳定配色），
  且即使 bundle 加载失败也能看出是哪一边。
- **顶部横幅**：dev 通道在 shell 最上方渲染一条横跨整宽的警示条（`role="status"`），文案明确写「开发版」
  与「非稳定代码」。它位于 `.app` 的第一个网格行，在任何断点下都不随工作区滚动。
- **橙色强调**：dev 通道把 `data-channel="dev"` 写到 `document.documentElement`，样式表据此覆盖
  `--accent` / `--accent-soft`（浅色与深色各一组），使主按钮、边框、焦点环、活动标签等既有强调面随之变橙；
  不改动其余语义色（危险/警告/成功）。
- **标题后缀**：dev 通道把文档标题与品牌区文本标为 `Codeestra DEV`，便于在多标签页中辨认。
- 标记只在 dev 通道出现，且**不隐藏任何功能、不新增交互、不改命令面**。

### D03：验收边界

- 可自动断言的部分（命令面）：通道纯函数的取值为 `dev`/`stable`；横幅组件在 `dev` 下渲染出角色与文案、
  在 `stable` 下渲染为空；样式表声明了 `:root[data-channel="dev"]` 的强调色覆盖、横幅规则，以及 `.app`
  的网格行仍包含 `minmax(0` （固定 shell 不回归）。
- 不可自动断言的部分：真实观感、窄屏换行、深色主题下的对比度、多标签页辨认度——这些是用户在场的人工确认。

## Consequences

- 两个界面在同一屏幕上可以立刻区分，代价是 dev 界面顶部少一条窄行的高度。
- 通道标记不进入稳定产物，因此提升不会把标记带入稳定分支，也不需要「合并时记得删掉」的人工步骤。
- 如果有人用 `bun run build:ui` 在 dev 检出构建（而不是 `build:ui:dev`），得到的是**未标记**的界面：
  这是刻意选择的 fail-visible-absent 行为（宁可少标，也不让稳定产物带上 dev 标记），文档必须写明正确命令。
- 新增一个根脚本属于开发便利面，不影响 Runtime 命令面；`just`/CI 未使用它。

## Verification

- `bun run --cwd apps/ui typecheck` 通过。
- 定向测试：新的通道测试文件断言纯函数取值（含大小写与空白不匹配）、dev/stable 下的静态标记、`index.html`
  的标记变换（dev 只改动两处、stable 原样返回），以及样式表中的覆盖规则存在、`.app` 仍是固定网格且首行为横幅行。
- 构建断言（命令面，读产物而不是看界面）：
  - `bun run build:ui` → `apps/ui/dist/index.html` **不包含** `data-channel` 与 `Codeestra DEV`；
  - `bun run build:ui:dev` → 两者都包含，且除该标记外与 `apps/ui/index.html` 的差异仅为正常注入的 asset 标签。
  （不能拿「grep JS bundle 里的横幅文案」当证据：两端 bundle 都含该字符串所属的代码，差异只在运行时的通道判定。）
- 人工确认：由用户在真实浏览器里看 dev 界面（横幅 + 橙色强调）与稳定界面（无标记）的对照。
