## 0. 为什么有这份清单

Codeestra 的第一原则里明确写着：**自动化测试与验收只用 CLI 命令与 Runtime 命令面驱动**，
**不使用 computer-use、OS 级键鼠或窗口自动化、桌面应用操作与真实桌面会话**（包括用浏览自动化驱动浏览器验证 UI）。
这条原则同时写在 `PROJECT_SPEC.md` §1.1 与 `AGENTS.md`。

后果是：**界面观感这一类事情没有任何机器断言，也不会被 CI 抓住。** 它能被确认的唯一方式是
**用户在场目视**。这份清单把「该看哪几项」写成可以打勾的条目，让这件事有据可查，而不是每次凭印象说「看着还行」。

> **这份清单不声称任何一项已经被机器验证过。**
> 它是给人用的：每条都给出「怎么触发」与「看什么」，不写「是否满意」。
> 已经跑过的机器断言（属性映射、样式表规则存在、纯函数取值）不在这里，它们在
> [docs/tasks/README.md](../tasks/README.md) 的记录里。

打勾方式：`- [ ]` 改成 `- [x]`，并在 §4 记下谁在什么时候核对了哪一组。

## 1. 准备

```sh
bun run codeestra status                # 确认 READY
bun run codeestra ui                    # 打开界面（地址里带 token）
```

界面里的所有设置都能用 CLI 改，也能在「设置」标签页改；两者写的是同一份值：

```sh
bun run codeestra settings ui list
bun run codeestra settings ui set theme dark        # 主题：system / light / dark
bun run codeestra settings ui set density compact   # 密度：comfortable / compact
bun run codeestra settings ui set fontSize small    # 字号：small / medium / large
bun run codeestra settings ui set motion reduced    # 动效：full / reduced
bun run codeestra settings ui reset                 # 全部恢复默认
```

**先准备一个有内容的项目**，否则大多数条目没东西可看：

- 至少 15 个任务（其中要有：一个在跑、一个等你回答、一个已合入 dev、一个已归档）；
- 至少有一条包含问卷的 Attention 和一个 `CONFIRM` 类 Attention；
- 至少有一个任务有原生终端（`session handoff admit` 成功过）与一段非空的执行过程。

没有这样的项目时，仍然可以核对布局类条目（外壳、窄屏、主题、密度、字号、动效、焦点），
但 Attention 卡片与终端面板两节只能标「未核对」。

## 2. 通用观察法（每一组都用这三步）

1. **改设置 → 看是否立刻生效**，并且**不用刷新页面**（除主题由系统切换驱动的那一项）。
2. **看有没有东西被推到视口外**：横向滚动条、被裁掉的文字、按钮跑到屏幕外边。
3. **看有没有出现「谁都不该看到」的东西**：重叠的文字、只剩图标的按钮、颜色对比度低到读不出字。

## 3. 逐项清单

- [ ] **A1** 把浏览器窗口高度缩到约 700px，打开一个任务很多、需要滚动的任务列表：

- [ ] **A2** 同上，**左侧导航的 `工作空间` 小标题与七个标签**没有跟着滚走。
- [ ] **A3** 同上，只有**中间的工作区**在滚动；滚动时导航栏与标题栏不抖动、不闪。
- [ ] **A4** 在任务详情里向下滚到「调度判定」段落，再回到顶部：**不会出现两个滚动条**打架。
- [ ] **A5** 底部页脚那一行（`关闭页面不会停止任务 · …`）在滚动时仍然可读。

### B. 窄屏（≤850px）

- [ ] **B1** 把窗口宽度缩到 **850px 以下**：左侧竖排导航变成**横向一条**，`工作空间` 小标题消失。
- [ ] **B2** 横向导航条可以左右滚动，**平级的七个标签**都能点到，没有标签被裁成半截。
- [ ] **B3** 侧栏底部的三个指示（`外观` 下拉框、权限模式文字、事件流状态）折行显示，
      没有互相压在一起。
- [ ] **B4** 标题栏仍然不随内容滚动；页面标题（`任务详情` 等）与右侧的状态文字**不重叠**。
- [ ] **B5** 任务列表的每一行在窄屏下仍然可读：`#编号`、规格摘要、状态微标、提示文字没有互相覆盖。
- [ ] **B6** 任务详情里的表格（执行记录 / 验证记录 / 集成记录）出现**横向滚动**而不是被压烂。
- [ ] **B7** 把窗口缩到 **620px 以下**：终端面板的「附加」「写入」「交还自动化」三组控件**竖排**，

- [ ] **B8** 窄屏下仍能从「任务工作台」切到「设置」并改一个设置项。

### C. 矮窗口

- [ ] **C1** 窗口高度约 600px、宽度正常：**底部停靠条仍然可见**（它是 sticky 的，不随内容滚出视口）。
- [ ] **C2** 同上，停靠条的三个字段与「＋ 创建草稿」**都在一屏内可操作**，
      即使需要滚动也能看到底部（它是 sticky 在正常流里）。
- [ ] **C3** 矮窗口下打开「运行事件」：事件列表区域滚动正常，`状态/游标/跟随/清空` 那一行始终可见。
- [ ] **C4** 矮窗口 + 长任务列表：标题栏与 `任务 N / M` 之间的间距没有被压成零。

### D. 三种主题

> 用 `settings ui set theme <值>`，或在侧栏「外观」下拉框里改。

- [ ] **D1** `system`（跟随系统）：改操作系统的浅色/深色开关，页面**实时跟随**，不需要刷新。
- [ ] **D2** `light`：钉住浅色，即使系统切到深色页面也不变。
- [ ] **D3** `dark`：钉住深色，同上。
- [ ] **D4** 三种主题下，**正文 / 次要文字 / 表格线 / 输入框边框 / 按钮**都能分辨，
      没有「深色下看不见的灰字」或「浅色下看不见的白字」。
- [ ] **D5** 三种主题下，**状态徽标**（执行中 / 等你处理 / 成果已提交 / 已合入 dev / 执行失败 /
      需要恢复）彼此**颜色可区分**，不是一片同色。
- [ ] **D6** 三种主题下，**错误横幅（红）与提示横幅（notice）**都能一眼认出，
      且横幅里的 `关闭` 按钮可见可点。
- [ ] **D7** 三种主题下，等宽区块（规格正文、事件 payload、终端投影、transcript 正文）
      的字色与背景有足够对比。
- [ ] **D8** 三种主题下，**终端投影区**里的控制字符占位（`␛` 之类）仍然看得清。

### E. 紧凑密度

> `settings ui set density compact` / `comfortable`。

- [ ] **E1** 切到 `compact`：卡片、任务列表行、表格行、问答选项、键值表的**间距明显收紧**，
      但**没有内容被裁掉**。
- [ ] **E2** `compact` 下任务列表一屏能看到的行数**多于** `comfortable`（这是它存在的意义）。
- [ ] **E3** `compact` 下表格的表头与数据行**没有黏在一起**，仍能分清哪一列是哪一列。
- [ ] **E4** `compact` 下按钮与输入框**没有被压得点不中**（尤其停靠条与终端写入行）。
- [ ] **E5** 切回 `comfortable`：恢复成默认节奏，没有残留的错误间距。

### F. 字号三档

> `settings ui set fontSize small` / `medium` / `large`。

- [ ] **F1** `small`：整体字号变小，**没有出现文字被容器裁掉**（尤其任务标题、状态微标、表格单元格）。
- [ ] **F2** `medium`（默认）：这是不选任何设置时的样子。
- [ ] **F3** `large`：整体字号变大，**布局没有被撑破**（卡片、表格、停靠条、终端写入行都还在框内）。
- [ ] **F4** 三档下**等宽区域（`pre`、终端投影、事件 JSON）随根字号一起缩放**，
      不是只有正文变了。
- [ ] **F5** 三档下**终端投影区的行宽**仍能读（不是每行只剩三四个字）。

### G. `reduced` 动效

> `settings ui set motion reduced` / `full`。

- [ ] **G1** `reduced` 下，任务列表里 `执行中` / `正在暂停` / `正在终止` 的状态点**不再动**。
- [ ] **G2** `reduced` 下，切换标签页、展开/折叠面板、出现横幅时**没有动画过渡**。
- [ ] **G3** `reduced` 只**减少**动效：无法通过它让本来不动的元素动起来。
- [ ] **G4** 即使 `motion` 是 `full`，当**操作系统**要求减少动效时，界面仍然减少动效
      （系统偏好是上界）。
- [ ] **G5** 切回 `full`：动效恢复，且没有残留的「永远不动」的元素。

### H. 键盘焦点顺序与 skip-link

- [ ] **H1** 打开页面后按 `Tab` 一次：第一个焦点落在 `跳转到工作区` 上（**它是页面上的第一个可聚焦元素**）。
- [ ] **H2** 按 `Enter` 触发它：焦点/视口跳进工作区，后续 `Tab` 从工作区内容继续，而不是回到标题栏。
- [ ] **H3** 连续 `Tab` 的顺序合理：品牌区（不可聚焦）之后是项目选择器 → 刷新 → 七个标签 → 页面内容。
- [ ] **H4** 每一个**当前可见**的按钮、输入框、下拉框、复选框都能被 `Tab` 走到，且**有一个能看清的焦点环**。
- [ ] **H5** 隐藏的按钮（按状态出现的那些，例如 `暂停`）**不会**被 `Tab` 走到。
- [ ] **H6** `Enter`/`Space` 能激活按钮；下拉框用方向键能选值。
- [ ] **H7** 任务列表里按 `Enter` 打开一个任务后，**焦点落在「← 返回任务列表」上**；
      返回之后焦点回到**你刚才那一行**（或列表标题）。
- [ ] **H8** 停靠条展开时焦点自动进入文本域；`Esc` 收起后焦点回到输入框。
- [ ] **H9** 终端投影区（只读文本块）能被 `Tab` 聚焦，并把焦点环显示出来。

- [ ] **J2-9** 调度页容量卡标题是 `Runtime 全局容量`，并且能读到「本次构建仍是项目级」的说明——

### K. Attention 卡片

> 准备：一条含问卷（1–4 题）、一条 `CONFIRM`、一条 `VALUE`。

- [ ] **K1** 卡片上 `N. [题头] 题干` 可读；多选时能看到 `（可多选）`。
- [ ] **K2** 每个选项的 `N. 选项名 — 选项说明` 能看清；选中状态**有明显视觉区别**。
- [ ] **K3** 单选的选项互斥、多选可以多选；同一题上**填了自定义回答会清掉选择**（反之亦然）。
- [ ] **K4** 一个问题都没答时，主按钮显示 `请至少回答一个问题` 且**不可点**。
- [ ] **K5** 答了 N 个问题后，按钮变成 `发送 N 个回答`，N 与你的操作一致。
- [ ] **K6** `CONFIRM` 卡片上是 `允许` / `拒绝`；`VALUE` 卡片上是输入框 + `发送`；
      非问卷卡片上能看到请求的原始 JSON。
- [ ] **K7** 把窗口缩到窄屏：选项文字、输入框、按钮**不溢出卡片**。
- [ ] **K8** 提交过程中整个卡片被禁用并显示 `正在发送回答…`（不能重复点）。
- [ ] **K9** 回答被拒（例如越界选项）时，错误横幅可见，卡片**仍然在 OPEN 列表里**，已答内容没被清空。
- [ ] **K10** 已回答/已关闭的请求收在折叠区 `N 个已回答或已关闭` 里，展开后能读懂每条的 `类型 · 状态 · 时间`。
- [ ] **K11** 任务详情里就地嵌入的那张卡片与「待处理」标签页里的那张**长得一样、行为一样**。

### L. 终端面板

> 准备：一个成功 `admit` 过、原生终端在 RUNNING 的会话。

- [ ] **L1** `会话 / Provider 会话 / 当前 incarnation / 写入租约 / side channel` 五行键值都能读懂，
      没有被截断到看不出是什么。
- [ ] **L2** `安全点与 fence` 要么显示 `已到安全点`，要么显示 `未到安全点` **并列出仍缺什么**。
- [ ] **L3** 四个按钮（`请求接管` / `接管（启动原生终端）` / `取消接管请求` / `刷新状态`）
      在不该点时**确实不可点**，并且把鼠标停上去能看到原因。
- [ ] **L4** `附加` 之前：输入框显示 `需要以写入者身份附加` 且不可用；以**观察者**身份附加后，
      输入框仍然不可用，并有一句说明。
- [ ] **L5** 以**写入者**身份附加后，输入框可用；`末尾附加回车（CR，等同按 Enter）` 复选有效。
- [ ] **L6** 终端投影区：控制字符显示成可见占位（`␛`），**没有把 ANSI 序列当控制指令解释**。
- [ ] **L7** 第二个客户端尝试以写入者身份附加时，界面报出 `ATTACHMENT_BUSY` 与当前 holder，
      **不排队、不伪装成功**。
- [ ] **L8** 投影被标记 `truncated` 时，界面**明说**「中间可能有缺失」，而不是默默少显示一段。
- [ ] **L9** `交还自动化（release）` 的结果横幅里写明「退出码只是审计数据，不参与判定」。
- [ ] **L10** 展开 `能力矩阵 · Runtime 自己报告的实现程度`：不支持的项**显式显示为不支持**，
      没有静默降级成「看起来支持」。
- [ ] **L11** 窄屏（≤620px）下终端的三组控件竖排后仍可操作，投影区仍有可用高度。

### M. dev 通道标记（已删除，ADR-0066）

## 5. 这份清单明确不覆盖的东西

- **功能是否正确**：那是 CLI / 命令面断言的事（`bun run codeestra …` + 测试），不是观感。
  需要真实 provider 在场执行的功能验收（并发、暂停/恢复、修订投递、知识消费、插件与 gate、散文提问、
  原生终端、真实提升）请走 **[真实 provider 端到端验收 runbook](../notes/real-provider-acceptance-runbook.md)**
  ——那一份按「前置 / 命令 / 预期观察 / 判定 / 失败中止 / 证据 / 清理」写功能验收，本文只管观感，两者不重叠、不互相矛盾。
- **数据是否正确**：同上。
- **性能**（滚动的流畅度、大列表的卡顿）：本文不设阈值，只标「有没有卡到不可用」。
- **无障碍合规性**：本文只覆盖键盘可达性与焦点顺序这一小部分，不声称符合任何标准。
- **跨浏览器差异**：本文只在一种浏览器上手工核对，不声称跨浏览器一致。
